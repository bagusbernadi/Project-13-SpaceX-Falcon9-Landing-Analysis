Project 13: SpaceX Falcon 9 Landing Analysis

Tujuan project: membangun pipeline data dan dashboard dari data publik peluncuran Falcon 9 yang menunjukkan faktor misi (orbit, payload, launch site, versi booster, reuse, tahun) yang paling terkait dengan keberhasilan landing first stage, sehingga kondisi misi dengan peluang pemulihan booster tertinggi dan estimasi nilai reuse-nya dapat dijelaskan dengan data.

Kategori:Rancangan projectAntariksa (Tech / Energi)Dataset publik + APISQL + dashboard

Project Introduction

Bayangkan perusahaan kurir yang mengantar paket dengan drone. Setelah paket dijatuhkan, drone harus terbang kembali dan mendarat utuh supaya bisa dipakai lagi. Paket yang berat atau tujuan yang jauh menghabiskan baterai, sehingga sisa tenaga untuk pulang tinggal sedikit. Model drone yang lebih baru biasanya lebih pandai mendarat.

Pemilik perusahaan ingin tahu: pengantaran seperti apa yang drone-nya paling sering kembali utuh, apakah drone yang sudah pernah dipakai sama andalnya dengan yang baru, dan berapa biaya yang dihemat karena drone tidak perlu dibeli ulang. Roket Falcon 9 menghadapi pertanyaan yang sama dengan skala jauh lebih besar.

Project ini membangun pipeline data, analisis faktor landing, dan dashboard: data peluncuran diambil dari SpaceX API dan Wikipedia, digabung dan dirapikan dalam satu database, lalu ditampilkan dalam dashboard dan peta. Project ini memperbarui repo capstone lama yang masih berupa notebook terpisah. Kata bergaris bawah putus-putus kuning bisa diklik untuk melihat artinya.

Gambaran alur kerja sebuah misi Falcon 9

Sebuah misi bisa dibayangkan sebagai tiga jalur. Dua jalur pertama terjadi pada setiap peluncuran. Jalur ketiga adalah yang dibangun di project ini.

  1. Jalur misi. Booster disiapkan, roket diluncurkan, payload dibawa ke orbit, lalu booster terbang kembali untuk mendarat. Seperti drone kurir yang pulang setelah mengantar paket.
  2. Landing gagal atau tidak dicoba. Sebagian booster gagal mendarat. Sebagian lagi memang tidak direncanakan untuk kembali, misalnya karena muatannya terlalu berat.
  3. Jalur kegagalan. Project mencari faktor yang paling terkait dengan keberhasilan landing: orbit, payload, launch site, versi booster, status reuse, dan tahun.
  4. Jalur data. Data diambil otomatis dari SpaceX API dan Wikipedia, digabung di database, lalu ditampilkan di dashboard dan peta. Hasilnya menjelaskan kondisi misi dengan peluang landing tertinggi.

1. BackgroundKenapa tema ini dipilih

Latar belakang masalah

Peluncuran roket sangat mahal, dan first stage adalah bagian termahal. SpaceX menekan biaya dengan mendaratkan first stage lalu memakainya lagi. Perusahaan peluncuran lain, calon pelanggan, dan analis industri ingin memahami kapan pendaratan berhasil. Repo capstone lama sudah menjawab sebagian pertanyaan ini, tetapi:

  • Analisis tersebar di banyak notebook kursus yang tidak bisa dijalankan ulang dari awal sampai akhir.
  • Data berhenti di sekitar 90 peluncuran, sehingga era Block 5 dan reuse booster belum terwakili dengan baik.
  • Fokusnya model prediksi, bukan penjelasan faktor dan dampak bisnis yang mudah dibaca.
  • Definisi "berhasil" belum dipisah antara landing yang gagal dan misi yang memang tidak mencoba landing.

Alasan memilih tema ini sebagai portofolio

  • Data publik yang mudah diverifikasi. Data peluncuran tersedia terbuka dari SpaceX API dan Wikipedia, dan bisa dicek siapa saja.
  • Menunjukkan perkembangan skill. Repo kursus lama diubah menjadi pipeline .py yang bisa dijalankan ulang, database SQL, dan dashboard publik.
  • Menunjukkan skill inti Data Analyst. Mengambil data dari API, scraping tabel web, menggabungkan dua sumber, analisis SQL, dan menyajikan temuan untuk pembaca bisnis.
  • Tingkat kesulitan mudah. Analisisnya deskriptif (persentase per kelompok, tren tahunan). Model klasifikasi hanya pelengkap.
  • Terhubung dengan project lain. Teknik scraping dan pipeline dipakai lagi di Job Market Scraping Pipeline (#31) dan Analytics Engineering Mini-Warehouse (#27).

4. DatasetDataset publik SpaceX API dan tabel peluncuran Wikipedia

Kenapa dataset ini? SpaceX API adalah API publik buatan komunitas yang mencatat setiap peluncuran, booster, dan landing pad. Tabel daftar peluncuran Falcon 9 di Wikipedia dipakai sebagai sumber kedua untuk cek silang. Keduanya sudah dipakai di repo capstone lama, jadi project ini sekaligus memperbarui pekerjaan sebelumnya.

Ukuran: sekitar 200 peluncuran Falcon 9 dari 2010 sampai sekitar 2022, saat API berhenti diperbarui. Kolom utama: tanggal, versi booster, nomor seri booster, payload mass, orbit, launch site, jenis landing, hasil landing, dan jumlah penerbangan booster (perkiraan, diverifikasi saat data diambil).

Catatan awal: sebagian payload mass kosong. Peluncuran setelah API berhenti bisa ditambahkan dari Wikipedia jika diperlukan. Ketentuan pemakaian kedua sumber dicek sebelum dipakai.

Sumber data (Wikipedia): here (Versi: revisi halaman saat diakses, Tanggal akses: 24 Oktober 2026)

Hipotesis yang akan diuji (belum terbukti)

1. Landing success rate naik tajam sejak sekitar 2016.

2. Block 5 hampir selalu berhasil mendarat.

4. Booster yang sudah pernah terbang sama andalnya dengan booster baru.

5. Landing di darat (RTLS) lebih sering berhasil daripada di kapal drone (ASDS).

5. ToolsAlat yang dipakai dan alasannya

Python (requests, pandas, BeautifulSoup)

Mengambil data dari SpaceX API, membaca tabel Wikipedia, membersihkan, dan menggabungkan data. Semua langkah ditulis sebagai skrip .py yang bisa dijalankan ulang dari awal sampai akhir.

Menggantikan notebook kursus yang terpisah-pisah di repo lama, sesuai rencana di daftar portofolio.

DuckDB + SQL

Database tempat semua tabel disimpan. SQL dipakai untuk success rate per tahun, versi, orbit, site, dan jenis landing, serta pencocokan API dengan Wikipedia. Perhitungan dibuat sebagai view.

Sesuai kolom Tools di daftar portofolio. Repo lama memakai SQLite; DuckDB lebih cepat dan konsisten dengan project lain.

Streamlit + Plotly

Membuat dashboard web dengan filter tahun, versi, orbit, dan site, scatter plot payload, serta peta launch site. Dipublikasikan gratis di Streamlit Community Cloud.

Sesuai daftar portofolio. Repo lama memakai Plotly Dash yang tidak dipublikasikan; Streamlit bisa dibuka lewat link.

scikit-learn (opsional)

Menjalankan ulang model klasifikasi dari repo lama sebagai pelengkap, lalu membandingkannya dengan aturan sederhana (Q11).

Model hanya pelengkap. Fokus project tetap pada penjelasan faktor dan tren.

GitHub

Landing success rate hanya dihitung dari misi yang mencoba landing. Biaya first stage diasumsikan US$40 juta untuk menghitung nilai reuse, dengan sumber publik yang dicantumkan di README dan label estimasi. Kelompok dengan kurang dari 5 misi tidak dijadikan dasar kesimpulan.

Hal yang perlu diwaspadai Usulan awal

Faktor saling terkait. Tahun, versi booster, dan reuse naik bersamaan. Kenaikan success rate tidak bisa dikaitkan ke satu faktor saja tanpa membandingkan di dalam kelompok yang sama.

Jumlah data kecil. Sekitar 200 peluncuran dibagi ke banyak kelompok membuat beberapa kelompok hanya berisi sedikit misi.

Sumber komunitas. SpaceX API dikelola komunitas dan berhenti diperbarui, sehingga ada kemungkinan data terlambat atau berbeda dari sumber resmi. Karena itu data dicek silang dengan Wikipedia.

1. ProblemPertanyaan yang ingin dijawab

Pertanyaan utama: Faktor apa (orbit, payload, launch site, versi booster, reuse, tahun) yang paling terkait dengan keberhasilan landing first stage Falcon 9, dan bagaimana tren success rate-nya?

Rancangan memecahnya menjadi 14 pertanyaan (9 Utama, 4 Pendukung, 1 Tambahan) dalam tema tren, kondisi misi, pemulihan dan reuse booster, dampak, dan validitas data. Daftar lengkap ada di bagian 2 halaman rancangan.
